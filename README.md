# Selenium UI-тесты YouTrack Server

Проект содержит UI-тесты YouTrack на Java 17, Selenium WebDriver и JUnit 5. ChromeDriver подбирается Selenium Manager автоматически. Для каждого тестового потока создается отдельный браузер; при ошибке JUnit сохраняет PNG в `target/screenshots` и формирует стандартные отчеты Surefire в `target/surefire-reports`.

## Запуск YouTrack

Docker уже установлен и запущен. Из корня проекта запустите контейнер:

```powershell
docker compose up -d
docker compose logs -f youtrack
```

Откройте `http://localhost:8080` и дождитесь первого запуска. При первом обращении YouTrack покажет мастер первоначальной настройки: завершите его, создайте администратора и обычный проект, например с ключом `TEST`. Запомните логин и пароль пользователя, который имеет право создавать задачи в этом проекте. Инициализация сервера может занять несколько минут.

Данные YouTrack сохраняются в именованных Docker volumes. Остановить сервис можно командой `docker compose down`. Для удаления вместе со всеми данными используйте `docker compose down -v`.

## Настройки и запуск тестов

Задайте переменные окружения в PowerShell и запустите Maven:

```powershell
$env:YOUTRACK_URL = "http://localhost:8080"
$env:YOUTRACK_USERNAME = "ваш_логин"
$env:YOUTRACK_PASSWORD = "ваш_пароль"
$env:YOUTRACK_PROJECT = "TEST"
mvn test
```

Можно задать те же настройки Maven-свойствами: `mvn test -Dyoutrack.url=http://localhost:8080 -Dyoutrack.username=... -Dyoutrack.password=... -Dyoutrack.project=TEST`. Для видимого окна Chrome добавьте `-Dbrowser.headless=false`; по умолчанию Chrome работает в headless-режиме.

Требуется установленный JDK 17+, Maven и Google Chrome. Параллельный режим JUnit включен в `junit-platform.properties`. Если тесты запускаются против другого экземпляра YouTrack, укажите его URL, ключ проекта и тестового пользователя в переменных окружения.

## Тест-кейсы

| № | Сценарий | Проверка |
|---|---|---|
| 1 | Вход с корректными учетными данными | После авторизации отображается интерфейс YouTrack |
| 2 | Вход с неверным паролем | Интерфейс показывает отказ авторизации |
| 3 | Просмотр списка проектов | На странице проектов виден заданный проект |
| 4 | Создание задачи | Новая задача создается в проекте и появляется в интерфейсе |
| 5 | Поиск задачи | Поиск по заголовку возвращает созданную задачу |

Данные для авторизации и задач лежат в `src/test/resources/testdata/*.csv`. Заголовки задач дополняются уникальным суффиксом, поэтому параллельные запуски не конфликтуют.
